## 詳細類別說明

### 1. Controllers Layer

#### PassportRecognitionController
- **職責**: 協調影像辨識和結果解析流程
- **屬性**:
  - `recognizer: IImageRecognizer` - 影像辨識器（依賴抽象介面）
  - `parser: IResponseParser` - 回應解析器（依賴抽象介面）
  - `DEFAULT_PROMPT_TEMPLATE: str` - 預設提示詞範本
- **方法**:
  - `recognize_passport(image_path: str, custom_prompt: Optional[str]) -> PassportInfo`
    - 執行護照辨識並返回解析後的結構化資料
  - `recognize_passport_raw(image_path: str, custom_prompt: Optional[str]) -> str`
    - 執行護照辨識並返回原始 LLM 回應
  - `get_default_prompt() -> str` (靜態方法)
    - 取得預設提示詞

### 2. Interfaces Layer

#### IImageRecognizer
- **類型**: 抽象基類 (ABC)
- **職責**: 定義影像辨識器的介面契約
- **方法**:
  - `recognize(image_path: str, prompt: str) -> str` (抽象方法)

#### IResponseParser
- **類型**: 抽象基類 (ABC)
- **職責**: 定義回應解析器的介面契約
- **方法**:
  - `parse(response_text: str) -> PassportInfo` (抽象方法)

### 3. Models Layer

#### ImageRecognizer
- **職責**: 實作影像辨識功能
- **實作介面**: `IImageRecognizer`
- **常數**:
  - `MAX_FILE_SIZE_MB = 15`
  - `MAX_FILE_SIZE_BYTES = 15 * 1024 * 1024`
- **屬性**:
  - `api_key: str` - Gemini API 金鑰
  - `model: GenerativeModel` - Gemini 模型實例
- **方法**:
  - `validate_image_path(image_path: str) -> Path`
  - `validate_image_size(image_path: Path) -> None`
  - `read_image_as_base64(image_path: Path) -> str`
  - `recognize(image_path: str, prompt: str) -> str`
  - `_get_mime_type(image_path: Path) -> str` (私有方法)

#### ImageSizeError
- **類型**: Exception
- **職責**: 圖片大小超過限制時拋出

#### ImageNotFoundError
- **類型**: Exception
- **職責**: 圖片檔案不存在時拋出

### 4. Parsers Layer

#### ResponseParser
- **職責**: 解析 LLM 回應為結構化資料
- **實作介面**: `IResponseParser`
- **方法**:
  - `parse(response_text: str) -> PassportInfo`
    - 主要解析方法，嘗試多種解析策略
  - `_try_parse_json(text: str) -> Optional[PassportInfo]` (私有方法)
    - 嘗試 JSON 格式解析
  - `_try_parse_key_value(text: str) -> Optional[PassportInfo]` (私有方法)
    - 嘗試鍵值對格式解析

#### PassportInfo
- **類型**: dataclass
- **職責**: 儲存護照資訊的資料容器
- **屬性**:
  - `passport_number: Optional[str]` - 護照號碼
  - `gender: Optional[str]` - 性別
  - `birth_date: Optional[str]` - 生日
  - `chinese_name: Optional[str]` - 中文姓名
  - `english_name: Optional[str]` - 英文姓名
  - `raw_response: str` - 原始 LLM 回應
- **方法**:
  - `to_dict() -> Dict[str, Any]` - 轉換為字典格式

## SOLID 原則應用

### 單一職責原則 (SRP)
- 每個類別只有一個變更的理由
- `ImageRecognizer`: 只負責影像辨識
- `ResponseParser`: 只負責回應解析
- `PassportRecognitionController`: 只負責流程協調

### 開放封閉原則 (OCP)
- 類別對擴展開放，對修改封閉
- 可透過實作 `IImageRecognizer` 介面來擴展不同的辨識引擎
- 可透過實作 `IResponseParser` 介面來擴展不同的解析策略

### 里氏替換原則 (LSP)
- 子類別可以替換父類別
- `ImageRecognizer` 可被任何實作 `IImageRecognizer` 的類別替換
- `ResponseParser` 可被任何實作 `IResponseParser` 的類別替換

### 介面隔離原則 (ISP)
- 介面精簡，只定義必要方法
- `IImageRecognizer` 只定義 `recognize()` 方法
- `IResponseParser` 只定義 `parse()` 方法

### 依賴反轉原則 (DIP)
- 高層模組不依賴低層模組，都依賴抽象
- `PassportRecognitionController` 依賴 `IImageRecognizer` 和 `IResponseParser` 介面
- 使用依賴注入模式，提高可測試性和彈性
