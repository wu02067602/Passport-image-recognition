## 時序說明

### 完整流程時間估計

1. **驗證階段** (< 10ms)
   - 檢查檔案存在
   - 檢查檔案大小
   
2. **讀取階段** (10-100ms，取決於檔案大小)
   - 讀取圖片檔案
   - 轉換為適當格式

3. **API 呼叫階段** (2-10秒，取決於網路和 API 回應)
   - 傳送請求到 Gemini API
   - 等待 AI 處理
   - 接收回應

4. **解析階段** (< 10ms)
   - 解析 JSON 或鍵值對
   - 建立 PassportInfo 物件

**總時間**: 通常 2-10 秒，主要取決於 Gemini API 的回應時間

## 並行處理可能性

目前系統為同步設計，未來可考慮：

1. **批次處理**
   - 同時處理多張護照圖片
   - 使用 asyncio 或 threading

2. **管道模式 (Pipeline)**
   - 驗證、讀取、API 呼叫、解析各階段獨立
   - 使用佇列 (Queue) 連接各階段

3. **快取機制**
   - 快取相同圖片的辨識結果
   - 減少重複 API 呼叫

## 錯誤處理策略

### 可恢復錯誤
- API 暫時性錯誤 → 重試機制
- 網路超時 → 增加超時時間或重試

### 不可恢復錯誤
- 圖片大小超過限制 → 立即失敗，返回錯誤
- 圖片檔案不存在 → 立即失敗，返回錯誤
- API 金鑰無效 → 立即失敗，返回錯誤

### 降級處理
- 解析失敗 → 返回原始文字，由使用者手動處理
- 部分欄位無法辨識 → 返回 None 值，其他欄位正常
